# 视觉导航调试平台

## 启动

需要 Python 3.8 及以上，无需额外依赖：

```bash
cd '视觉导航备赛工具/平台'
python3 server.py
```

在本机浏览器打开 http://127.0.0.1:8766 。Ctrl+C 退出；也可用 `--port 端口号`。

## 功能

- 控制台界面基于 `/Users/july/Project/ricecar/car/racecar_ui.html` 复制并适配，原仓库不受修改；新增视觉赛道页和本地模拟 API。只实现模拟遥控、停止与地图，其余车端功能需要对应接口。
- `data/track.json` 是赛道矢量数据：边界采用 SVG path 字符串、地标、斑马线、挡板示意和起点均为数据；网页 SVG 动态绘制，不使用图片。绘图坐标来自任务书示意图的人工描绘，比例和形状待正式赛道数据校准。
- 地图定位当前显示模拟车辆的二维姿态，不是实际传感器定位。`metric_calibration` 为 null，后续可用标定程序替换数据及建立绘图坐标到实地坐标的变换。
- 遥控页沿用 ricecar 的方向键和滑块，按住前后左右按钮或 WASD/方向键，释放停止。模拟器 0.5 秒内未收到命令则停止，页面的停止按钮立即停车；物理急停和车辆安全锁还未接入。
- 后端使用 Python 标准库、只监听本机，接口为 GET `/api/track`、GET `/api/state`、POST `/api/command`。现阶段仅有模拟底盘，不会向车辆发送命令。

## 实车接入计划

先确认 ROS 2 发行版、图像话题、底盘指令消息类型、坐标约定和急停接口。再实现单独的 ROS 2 底盘适配器，将模拟与实车模式明确隔离；设置限速、命令超时、断连停车和硬件急停，并先架空车轮测试。不得把图上模拟位置直接作为实车定位输入。

先查看真实话题及类型：

```bash
ros2 topic list -t
ros2 topic info /替换为实际图像话题 -v

```

复制本平台的 `ros2/telemetry_bridge.py` 到小车；source 小车实际 ROS 2 及其工作区环境。在小车上，使用实际话题替换下面的示例（compressed 需要 `sensor_msgs/msg/CompressedImage` 的 JPEG；raw 需要 `sensor_msgs/msg/Image`、`cv_bridge`、OpenCV）：

```bash
python3 telemetry_bridge.py --camera-topic /实际图像话题 --camera-type compressed --odom-topic /实际里程计话题
```

不传相机或里程计参数时只查看 ROS 2 话题图谱，不订阅默认猜测的话题。若只想查看一项，省略另一项即可。里程计订阅需 `nav_msgs/msg/Odometry`。Mac 端建立 SSH 隧道（用户名与地址请换成实际值）：

## ROS 2 图像与速度指令采集

`ros2/record_dataset.py` 与 `ros2/dataset_session.py` 必须放在小车的同一目录。确认小车实际 ROS 2 版本与话题类型后，先 `source` 小车的 ROS 2 环境，并运行 `ros2 topic list -t`、`ros2 topic info <话题> -v` 核实相机及人工遥控输出的指令话题；再在“数据 · 训练 · 推理”页填写话题、消息类型和小车上的新目录，生成可复制的命令。支持 JPEG `CompressedImage` 或经 cv_bridge/OpenCV 转换的原始 `Image`，以及 `Twist` / `TwistStamped`。

采集过程只订阅，不向底盘发指令；启动后用已确认的手柄或遥控系统操作。输出目录必须不存在，采集会创建 `images/`、`data.csv` 和 `metadata.json`，不会覆盖既有目录。默认每秒最多 5 帧，只有过去 250 毫秒内收到有效控制指令才保存；超时跳过。按 Ctrl+C 结束，或达到默认 3000 帧后停止。可调整 `--hz`、`--max-command-age-ms` 和 `--max-images`。

CSV 中的 `linear_x`、`linear_y`、`angular_z` 是图像到达时最近接收到的**控制指令**，并非实测速度；`command_age_ms` 是进程接收时间差，`image_stamp_ns` 是图像头时间戳，不能证明精确同步。本机训练可整理此格式并用 `angular_z` 作为标签；它与厂家历史数据标签的实际来源并不相同。若采集不到帧，检查命令话题是否持续发布、QoS 和类型，再根据实际频率配置过期阈值。

## 任务逻辑离线演练

“数据 · 训练 · 推理”页的“任务逻辑演练”会运行固定的模拟事件：人行道连续静止反馈满 3 秒、障碍出现/清除和两圈计数。代码位于 `mission/task2.py`，没有 ROS 连接、摄像头感知、避障轨迹生成或底盘发布能力。它将来需要由经过验证的感知和里程计事件驱动；不能单凭此演练判断车辆能否完赛。

计圈需要外部提供可靠的起点线离开和进入事件，避免重复计数；停车计时需要持续、足够新鲜的静止反馈，反馈中断或车辆移动会重新开始计时。障碍出现时该逻辑给出停止建议，障碍绕行另需真实规划和现场验证。比赛录像和成绩以实际运行视频和官方要求为准。

## 计时 · 自测记录

在侧栏选择“计时 · 自测记录”：

1. 前轮接地处经过起点线时点击“开始计时”；每圈前轮接地处再次经过起点线时点击对应按钮，第二圈结束后计时冻结。
2. 每圈在人行道停稳时点击“记录停车”，开始行驶时点击“记录结束停车”；错误标记可在本圈清除。
3. 赛后观看比赛录像，填写核对过的比赛用时、两圈停车时长、播报情况、碰撞/压线/干预次数、各项罚时和备注，点击“保存复核”。
4. 八项罚时全部填写后计算罚时合计；同时填写视频核对用时后计算有效时间。无罚时填 0，尚未核对留空。不会根据次数自动套用任何费率，因为任务二自测表与原通知的若干罚时和失败条件不同，应按赛事方最终确认的口径填写。
5. 记录写入 `data/比赛记录/run-*.json`，可在页面选择以往记录并导出 JSON。人工计时会受到操作和网络延迟影响，仅用于辅助复核；自测表的最终用时请依正式视频核对。这里不上传或提交赛事成绩。

标记自动保存；赛后填写或修改的复核字段需要点击“保存复核”。页面刷新不会清除已保存结果；服务停止或重启时仍在进行的计时将标记为“中止”，不会自动恢复或伪造完成时间。计时与遥控独立，不启动、停止或干预车辆。复核表中的两圈停车时长与现场按钮计时分别保存，便于对照。

新增组件：

- `automation/detector.py` 根据图像区域中白色条带的数量检测起点线与人行道；`data/perception.example.json` 为可调整的示例，不代表实际赛道或摄像头。该方法是待验证的传统图像处理原型，尚未证明在实车场景可靠，也不是训练好的深度学习模型。

- `ros2/serial_voice_player.py` 控制实车语音盒，使用厂商的固定停车提示。该设备不支持直接播放自定义 WAV；当前固定语音未确认包含完整礼让内容，平台在停车时会显示完整文字。串口回执表示指令已写出，不等同于声音或内容验证。`ros2/announcement_player.py` 则供有普通音频输出设备的车辆使用。
- `ros2/camera_node.py` 与 `ros2/deepbot_base.py` 在本车上直接读取相机和底盘反馈，底盘接口默认不接受运动指令；`ros2/vehicle_preview.sh` 管理只读预览。`ros2/command_gate.py` 是可选速度仲裁接口，默认不发布到车辆；必须明确启用，且需要新鲜的循迹指令、自动任务状态和独立安全监测许可。任何一项失效、停车或完赛时输出零速度。
- `ros2/openvino_preview.py` 使用车端原厂 `race.xml` / `race.bin` 对图像进行独立模型推理。模型结果供观察，不参与停车或计圈决策；尚需在正式赛道上验证。`tools/ros2_camera_calibrate.py` 可采集棋盘格照片并计算相机内参，输出单独保存，标定模板和打印步骤在上级目录 `标定/`。

### 图片检查和标定

#### 自助相机标定

在“摄像头 · 感知 → 相机标定”中可独立完成采集：

1. 输入棋盘格内角点数量和实测方格边长，点击“新建采集组”。当前棋盘格为横向 8、纵向 6、方格 20 mm。
2. 把棋盘格贴在平整硬板上，保持车辆和摄像头固定。让完整棋盘格入镜，调整位置、距离和倾斜角度，在清晰稳定时点击“拍摄当前画面”。每点一次保存一张；可随时关闭页面，之后选择原采集组继续。
3. 在照片列表查看棋盘格是否被识别。照片可排除或恢复，原图保留。也可导入这台相机拍摄的 JPEG/PNG，同一组应使用相同相机和分辨率。
4. 至少准备 12 张识别到棋盘格的照片，建议 15 张以上，覆盖画面上下左右和不同倾斜角度。点击“计算标定”会在本机保存 ROS 格式 YAML，并显示误差；支持下载参数，或将照片和结果打包导出。

照片及结果位于 `data/相机标定/`，断开小车后仍可基于已保存照片计算。结果仅写入本机采集组，不会自动替换小车的相机参数；拍摄相机、分辨率和实际尺寸应与使用时一致。新拍或调整参与计算的照片后，需重新计算才能得到对应结果。自动筛除的模糊或偏差较大的图片仍会保留在采集组中。

标定计算环境已在本机的 `.venv-calibration` 中配置。重建环境：

```sh
python3 -m venv .venv-calibration
.venv-calibration/bin/python -m pip install -r requirements-calibration.txt
```

也可使用 `python3 tools/calibration_cli.py --help` 查看命令行的建组、拍照、导入、排除、计算和导出命令；拍摄从 8770 本地桥读取画面，计算时不需要连接小车。

本机图片检查需要 Python 的 NumPy 和 Pillow；例如本机已配置的运行环境可执行：

```sh
/Users/july/.cache/codex-runtimes/codex-primary-runtime/dependencies/python/bin/python3 tools/inspect_frame.py '相机图片路径' --config data/perception.example.json --output /tmp/visual-race-inspection.jpg
```

图像标记显示两个检测区域、条带数和检测结果。复制示例配置到新文件，使用赛道现场不同位置、光照和行驶方向的多张相机图片调整 ROI（归一化坐标）、条带方向、白色阈值和条带数量。应同时覆盖人行道、起点线、普通车道线与空白地面，观察漏检和误检。根据车辆和摄像头的几何关系实测触发位置：起点计时按前轮接地处越线、人行道需要在规定位置停稳；三帧确认还会产生延迟。完成现场检查后，才把新配置中的 `calibrated` 设置为 `true`。此开关只表示操作员完成了标定，不自动证明识别准确。

### 小车开机后的接入顺序

1. 先核实小车实际使用的 ROS 版本、相机消息类型、里程计、循迹输出和底盘控制话题。以下适配器基于 ROS 2；若小车实际是 ROS 1，需要按其接口适配，不能直接运行 ROS 2 程序。车端需要 `rclpy`、ROS 消息包、NumPy 和 Pillow。摄像头可使用 JPEG 压缩图像，或 `rgb8`、`bgr8`、`mono8` 原始图像。图像和里程计的头时间戳需与节点 ROS 时钟一致，零时间戳、过期及明显超前的数据会被拒绝，源时间最大延迟可通过 `--max-source-age` 调整。
2. 将 `automation/`、`ros2/`、`data/prompts/` 和标定配置一同复制到小车，保持目录结构。分别验证相机画面、检测区域、里程计静止读数和扬声器。在平台已有只读桥中添加 `--mission-topic /visual_race/status` 后，页面可显示自动任务状态。
3. 启动 `ros2/announcement_player.py` 时填写车端播放器的绝对路径和两段 WAV 路径；启动 `ros2/automatic_race.py` 时填写实际相机类型、图像和里程计话题、标定配置以及事件目录。例如按 `--help` 查看各项参数。启动后用 ROS 2 的 `/visual_race/arm` Trigger 服务准备任务，`/visual_race/stop` 停止，`/visual_race/reset` 复位；两个检测区需处于未检测状态且相机、里程计数据新鲜才能准备。
4. 循迹、避障和红绿灯识别不是这个条带检测器的一部分。接入速度仲裁前，需要能够连续提供可靠的循迹速度和独立安全监测 Bool 话题，确保障碍、红灯、紧急停止和监测故障时不给通行许可。确认底盘驱动有指令超时停止、急停可用，并确保其他程序不会绕过仲裁直接向底盘发布速度。之后按 `ros2/command_gate.py --help` 填入实际话题、低速限制及 `--activate`，先架空或在安全场地逐项验证，再进行低速实车联调。

摄像头的检测区域与前轮实际接地处并非同一个传感器，画面延迟、帧率和车速都会影响计时与停车位置。示例配置没有经过现场测试；完成标定和联调前不应作为正式比赛的自动成绩。
