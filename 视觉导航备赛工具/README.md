# 视觉导航今日备赛工具

这是准备与检查工具，不是已经完成的自动驾驶程序。不要在不了解接口的情况下驱动小车；上电测试时让人员远离车轮并准备随时断电。

## 1. 收集小车环境

把本目录复制到小车，在小车 Linux 终端运行：

```bash
bash scripts/doctor.sh | tee robot-diagnostics.txt
```

如果 ROS 2 存在但未加载，可先按实际安装版本执行 `source /opt/ros/<发行版>/setup.bash`，然后再次检查。输出检查 `/opt/ros`、工作区、摄像头、串口、运行中的 ROS 节点及话题，不包含账号密码。运行图谱仅反映当时已启动的节点。检查输出并发回，以便确认摄像头、底盘命令话题、现有程序和 ROS 版本。不要发送密码、密钥。

## 2. 验证最小闭环

1. 确认赛事指定 ROS 2；查看厂家工作区及启动说明，确定是否可复用。
2. 支起车轮，按厂家指导检查前后和转向方向，记录可立即停车的方法；再低速落地测试。
3. 检查摄像头话题、帧率及视野，采集正式灯光下的车道、斑马线、挡板画面。
4. 找到厂家视觉导航程序，先只看识别效果，再低速验证车道控制；逐一验证停车、播报、绕挡板和两圈。
5. 进行完整无干预演练；如无现有程序或模型，不能假定该工具已经实现导航。

## 3. 比赛成绩和提交

使用 records/演练记录.csv 逐次记录；运行 `python3 scripts/score.py --time 120 --penalty 10 --penalty 20` 仅演示加法。实际罚时、失败条件及是否叠加必须按最新任务二自测表核实：群里出现压线 5 秒和 10 秒不同口径，尚未确认适用任务。

10 月 31 日 20:00 为群公告所列线上赛截止时间；若团队要求今天完成，按团队内部期限执行。任务二在线表只能提交一次，确认视频与数据后再填。作品网盘链接设永久有效及提取码，技术报告、自测表 PDF、视频的格式与命名以最新群文件为准。

## 4. 不做假设

旧版 DEEPBOT 手册使用 ROS 1；比赛规则要求 ROS 2。2025 镜像备份源系统为 Ubuntu 20.04.6；不能仅凭此判断其 ROS 版本。不要直接恢复镜像，它会覆盖目标磁盘上的数据。

## 5. 采集 ROS 2 摄像头样本

确认已启动相机，并通过 `ros2 topic list -t` 找到类型为 `sensor_msgs/msg/Image` 的真实话题，再运行（示例话题需替换）：

```bash
python3 scripts/capture_ros2.py --topic /camera/image_raw --out data/track --interval 1 --count 100
```

需要小车环境中已有 `rclpy`、`sensor_msgs`、`cv_bridge` 和 OpenCV。脚本仅订阅图像，不发布运动指令；话题可能因相机驱动、QoS 或图像类型不同需要调整。Ctrl+C 可停止采集。

## 6. 赛道电子示意图

先按 `平台/README.md` 启动调试台；`map/赛道查看器.html` 会跳转至平台。`平台/data/track.json` 存放矢量地图数据；`map/地图说明.json` 保存原示意图的来源与坐标约定。图中标号不是行驶路径点，4 × 4.5 米未经证实，不能把示意图直接拉伸成米制定位地图。正式定位需官方赛道原图或现场实测、相机标定及 ROS 2 传感器坐标系，挡板还需实时感知。

## 7. 版本库与本机资料

版本库保存平台代码、矢量地图、现有标定照片与参数、训练模型和评估记录，以及比赛通知和自测表。为控制体积，Python 虚拟环境、厂家镜像与视频、参考训练图片及生成的部署压缩包不纳入版本库，这些文件仍保留在本机。数据划分 CSV 和元数据已保存；在新机器复现训练时，需要另行准备对应图片并安装依赖。
